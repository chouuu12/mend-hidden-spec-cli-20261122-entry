## The task
Build `mend`, one command-line tool that reads all four AI edit formats to one written specification (SPEC.md ships in the kit's starter) and changes every file or none:
1. Unified diff (often with wrong line numbers) — search for the context, do not trust the line numbers.
2. SEARCH/REPLACE blocks.
3. V4A patch format (markers: `*** Begin Patch`, `*** Update File: <path>`, `*** Add File: <path>`, `*** Delete File: <path>`, `*** End Patch`; `@@` hunks with `+`/`-`/space lines).
4. Text-editor tool calls as JSON (e.g. str_replace/create/insert commands with path, old_str, new_str).
Find the lines an edit names even when the model drifted their whitespace or indentation. A check is one run of the CLI in a fresh directory (arguments, stdin, starting files); it passes when the exit code, everything written to stdout, and every file afterwards are exactly what SPEC.md says. The 100 practice checks are public with the house reference's outputs. The 100 scored checks of each instance are drawn after the deadline from a sealed pool of 300 that no kit carries, and include kinds of check the practice set does not show, each testing a sentence of SPEC.md — so implement the SPEC completely, do not just fit the practice set. The house enters a strict applier as a house entry in the last hours: a reward needs a score above it, and it holds the place it finishes in and never takes that place's reward.

## Numes second opinion (deepseek/deepseek-v4.1-flash:free, cost 0)
- Matching tiers, in order: (1) exact line match; (2) whitespace-normalized (trim each line, collapse internal space/tab runs for matching only); (3) indentation-tolerant (ignore leading indentation, preserve relative indentation of the replacement); (4) fuzzy (normalized token/Levenshtein similarity with a threshold) as last resort.
- Atomicity: parse and resolve ALL edits in memory first, validate non-overlap, compute every file's final content, and only then write (temp files in the same directory + rename; keep backups so a mid-write failure can roll back). If any edit fails to resolve, write nothing.
- Determinism: stdout exactly what the spec says and nothing else; stable exit codes (mirror SPEC.md: e.g. 0 success, 1 apply failure, 2 usage/parse — read the spec, do not invent); never print debug output; keep times and randomness out of everything; flush output before exiting (set process.exitCode, do not call process.exit mid-write).
- Likely hidden-spec traps: path traversal outside the working directory; CRLF vs LF and final-newline preservation; overlapping/conflicting edits to the same file; multiple hunks per file applied in sequence; replacement indentation when the old block's indentation drifted; empty-file and delete-file edge cases; duplicate identical context lines (pick the right occurrence per the spec's rule).
